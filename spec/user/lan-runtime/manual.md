# 局域网统一工作台使用手册

## 启动

在仓库根目录运行：

```powershell
python start_all.py
```

终端会显示本机和局域网访问地址。把局域网地址发给同事即可；不要单独转发各子服务的随机端口。停止时回到启动终端按 `Ctrl+C`，程序会一起关闭全部工作台。

浏览器访问终端显示的根地址后会进入 `/tool/` 首页；这是首页样式和脚本的规范资源路径。

常用参数：

```powershell
python start_all.py --port 4567 --idle-minutes 3
python start_all.py --no-build --no-open
```

## 使用状态

所有人都能查看首页、API 文档和工作台，并共享当前服务中的任务状态和结果；Cookie、Session 和业务状态按应用分别保存。第一位进入任一具体入口的 IP 会显示为当前使用者；其他 IP 会在顶部看到该 IP 和“接管使用”，但不会因为占用提示而无法打开或操作页面。

当前使用者的页面会自动续期。其他人确需操作时可点击“接管使用”，接管不会停止已有任务或清除页面结果。操作结束且没有任务运行时点击“结束使用”，页面会返回工具首页；如果任务仍在运行，需要等待完成或先按该工具规则停止。连续 3 分钟没有活动且没有任务运行后，下一位进入工作台的人会自动成为当前使用者。接管、结束和自动换人都不会清空 Cookie、任务状态或结果。

## Cookie 管理

API 文档只管理 API 文档进程自己的 Cookie，可以直接粘贴某个系统的 Cookie/cURL 并验证，也可以点击“导入 Cookie”选择 `csn2api-cookies-*.json` 或同内容 TXT；点击“导出 Cookie”可保存 API 文档中仍有效的规范化 Cookie。每个普通工作台保留自己的 Cookie 输入和验证按钮，必须在该工作台单独验证；API 文档不会把 Cookie 自动分发给工作台。

Cookie 文件包含明文登录凭据，只放在受控本机，不发送给他人，不上传仓库或聊天。服务重启后可在对应应用重新导入或粘贴；API 文档导入失败只影响 API 文档，工作台验证失败只影响当前工作台。单独启动某个 APP 时，该 APP 仍使用自己的 Cookie 输入和进程内会话，不依赖 `start_all.py` 或 API 文档正在运行。
