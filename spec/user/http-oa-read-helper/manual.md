# OA 已阅助手（HTTP版）使用手册

## 启动

在应用目录安装依赖：

```powershell
pip install -r requirements.txt
python start.py
```

程序只在本机 `127.0.0.1` 启动，并打开本地工作台。

## 1. 验证凭据

验证成功后，凭据区会显示该 OA Session 对应的“员工号 · 姓名”。身份只保存在当前页面和后端进程内存，刷新、主动清除或会话失效时与 Cookie 同步删除。

在已登录 OA 的浏览器打开 F12 Network，等待登录重定向和回调完成并进入待办列表。优先选择域名为 `work.csair.com`、路径包含 `/oai/work/box/query/waiting` 的待办请求，右键选择 Copy as cURL；`/oai/work/login/userInfo` 或其他携带 Cookie 的 `work.csair.com` 已登录业务请求也可以。不要选择 IAM 登录域、回调中间页、静态资源或请求头中没有 Cookie 的请求。把完整内容粘贴到“cURL 或 Cookie Header”，点击“验证凭据”。

OA 优先粘贴完整 cURL，不要只从其他页面抄一段 Cookie。完整 cURL 会同时提供该浏览器的 User-Agent；如果 OA Session 绑定浏览器上下文，这比纯 Cookie 更可靠。工作台只复用 Cookie 和白名单内的 User-Agent，不执行 cURL，也不透传 Authorization 或其他任意请求头。

验证通常很快完成。页面在 OA 响应前显示“验证中”；连接超过 5 秒或读取超过 10 秒会显示超时。OA 返回重定向通常表示当前 Cookie 被送回登录流程，工作台不会自动跟随并误判为有效。

验证成功后输入框会清空，当前页凭据面板显示规范化 Cookie 并提供“复制凭据”。内容只存在当前页面内存；刷新或关闭页面、主动清除 Session 或会话失效后立即删除，页面不会把凭据写入浏览器持久化存储或文件。

## 2. 扫描全部待办

点击“扫描全部待办”。页面读取全部分页并显示：

- 全部待办数。
- 可处理的同类公文数。
- 不同类型跳过数。
- 每个模块的数量、动作和完整示例标题。

当前只有 `DOC/official-document` 公文模块会执行已阅。其他类型全部跳过，不会调用公文接口。

## 3. 选择数量

指定数量模式输入任意正整数，不设置最大值。输入 10 就处理 10 条；输入 20 就处理 20 条。输入大于当前同类公文数时，工作台自动处理全部同类公文，不会因为超过数量报错。页面会在开始前显示本次实际处理数量。

无限模式是页面默认模式，处理本次扫描中的全部同类公文，直到同类公文处理完。不同类型仍然跳过，不会因为异类留在列表而继续循环。

两个模式按钮都显示圆形选择标记，当前选中项有背景、边框和文字高亮。需要只处理一部分时切换到指定数量模式并输入数量。

## 4. 开始已阅

点击“开始已阅”，工作台按当前选中的无限模式或指定数量模式开始执行。

工作台按列表顺序逐条处理。页面显示当前完整标题、进度、成功和失败数量，逐条结果表显示完整标题、模块、状态和结果。

每条已阅只提交一次。接口返回成功后，工作台立即记录成功并继续下一条，不额外查询待办或等待记录消失。已阅请求的 HTTP 异常、响应结构异常、业务码异常或其他异常，都会只把当前条目标记为失败并继续；只有登录会话失效才会停止本批。

## 5. 终止和继续

点击“终止”后，工作台完成当前已阅请求，再在记录边界停止。已经完成的结果保留在当前页面状态中。

批次完成、失败或终止后，先重新扫描，再开始下一批。刷新页面不会清除本地 Python 进程内的 Session，但页面不会自动恢复明文 Cookie；服务退出、主动清除或会话失效后需要重新导入或粘贴验证。

## Agent HTTP 入口

`POST /api/start` 可以串联凭据验证、扫描和开始已阅。请求字段：

```json
{
  "credentials": "Cookie: ...",
  "runMode": "finite",
  "maxCount": 10
}
```

`runMode` 使用 `finite` 或 `all`；`finite` 对应指定数量，`all` 对应无限模式并作为缺省值。调用方通过 `GET /api/status` 轮询阶段、分类、进度和逐条完整标题结果。
