# 训练安排查询（HTTP版）开发规格

## 产品边界

本工具是独立本地 HTTP APP，只读访问 IEB 已结束训练安排。用户提供当前已登录 Cookie Header 或 Copy as cURL；凭据只保存在本进程内存中。APP 与 API 文档共用 `ieb_protocol.training_arrangement`，共享动态类别、日期窗口、请求、分页、表格解析和会话失效合同。

## 单类别查询

验证凭据后独立加载当前门户训练类别。用户选择一个动态类别、周/月/年范围和结束日期后，工具按周期和页码严格串行查询，页面展示完整动态列，Excel 包含周期汇总和各周期明细。

## 区域默认配置

区域默认模式固定查询周、月、年，并按以下业务类型归类：

- 区域航线：特殊区域、航路和机场训练
- 区域报务：英语通信单飞航线检查
- 副驾驶转A2：副驾驶转标准训练(A2)
- 副驾驶转B：副驾驶转标准训练(B)
- 副驾驶转C：副驾驶转标准训练(C)
- 副驾驶转D：副驾驶转标准训练(D)
- 机长年度：机长年度航线检查
- 航线一检：STC机长转机型一级航检、非STC机长转机型一级航检（大转重）、非STC机长转机型一级航检（非大转重）
- 航线二检：非STC机长转机型二级航检
- 机长转C：机长等级训练B转C
- 机长转D：机长等级训练C转D

静态配置只保存业务类型和中文科目名称，门户内部代码每次从动态类别中按去空白后的完整名称唯一解析。任一科目缺失或重复时禁用默认模式并显示具体错误，不猜测内部代码或近似匹配。

查询区始终从后端状态读取并以单列清单展示默认配置，每个业务类型占完整一行并直接列出所属训练科目；未验证凭据时也可查阅。加载门户动态类别后，清单保持可见，并由同一区域显示是否已经完整匹配当前门户。

默认模式按配置顺序、科目顺序和周/月/年顺序严格串行。每完成一个周期，protocol core 立即发布当前周期结果，manager 随即刷新已聚合的分类汇总和明细；页面轮询可实时显示已完成数据、当前类型、当前科目、周期、页码和科目进度。航线一检的三个科目按同一类型和周期合并，同一真实安排被多个科目返回时按完整业务行去重。

## 统计与导出

只有“员工号/姓名”字段能同时解析出员工号和括号内姓名的行才是有效业务记录；空表、缺少员工号或姓名的行，以及“没有训练班人员信息”等门户占位行均不计数，即使其他单元格仍有序号、操作文字或状态。每条有效训练安排计为 1 人次。`训练状态=完成`计为通过，`训练状态=终止`计为不通过；这是仅有的两种业务状态。出现空值或其他状态时停止默认导出并报告契约变化，不生成可能失真的最终通过率。

通过率为当前类型、当前周期的通过人次除以总人次；无记录显示 `/`。Excel 包含“分类汇总”和“明细”两个 Sheet：“分类汇总”按类型展示本周、本月、年度的人次和通过率；“明细”对同时属于周、月、年的同一真实安排只保留一行，以“所属周期”标记周、月、年，并保留区域类型及门户全部明细列。

## 错误与停止

登录失效立即停止后续请求并清除当前会话。HTTP、表头、分页或训练状态合同异常时停止本次默认查询，不自动重试。人工停止在当前 HTTP 请求返回后生效；已经发布到页面的阶段结果继续可见，只有完整完成时生成最终 Excel。

## 本地接口

- `POST /api/session/verify`：验证并保存当前 APP 会话。
- `POST /api/metadata/load`：加载动态类别并校验区域默认配置。
- `POST /api/run`：单类别查询；`mode=area-default` 时执行区域默认配置。
- `POST /api/stop`：请求在当前请求完成后停止。
- `GET /api/status`：返回脱敏会话、实时进度、阶段汇总、明细和下载状态。
- `GET /api/download/<file-id>`：下载 manager 登记的结果 Excel。
